# Dependências de contrato da Tenant API

Este registro separa decisões de produto já aprovadas de contratos que o
Tenant Web realmente pode consumir. Ele não substitui o glossário nem os ADRs
da Tenant API e não autoriza o frontend a simular estados, evidências ou
permissões.

## Estados usados

- `api-contract-not-published`: a decisão existe, mas falta contrato utilizável;
- `api-contract-local-unpublished`: há implementação na worktree local da API,
  ainda sem referência publicada e sem prova em produção;
- `frontend-integrated`: o Tenant Web já consome o contrato real;
- `verified`: existe evidência ponta a ponta no ambiente declarado.

Nenhum item abaixo está `verified` em produção. A revisão de 1º de setembro de
2026 usou a revisão local `efba48e` da API; isso comprova o código auditado, não
publicação nem execução em produção.

## Contratos integrados nesta etapa

- Encerrar o atendimento humano usa o comando versionado
  `POST /whatsapp/conversations/:id/actions/return-to-bot`; o painel não usa
  nem expõe `actions/close` como sinônimo dessa decisão. O adapter continua
  reconhecendo `close` como estado técnico temporário e `close-after-rejection`
  como alias legado. O próximo inbound reabre a mesma conversa; não existe
  fechamento definitivo. A interface e a Server Action exigem escopo Comercial
  e conferem se o usuário autenticado é o atendente responsável. A Tenant API
  aplica a mesma verificação na transação versionada.
- A criação de conta interna continua usando `POST /users`, mas o frontend aceita
  somente `documentAccessMode=standard`. O schema e as Server Actions também
  rejeitam payloads forjados de candidato ou cliente.
- Contas legadas `document-portal` e `client` continuam compatíveis com leitura,
  login e edição. O modo persistido é somente leitura e a Server Action compara
  o valor atual antes de qualquer atualização. Mudanças de departamentos,
  permissões ou vínculo também são comparadas com a resposta autoritativa; uma
  divergência é tratada como conflito, nunca como sucesso.

Esses itens estão `frontend-integrated` e cobertos por testes locais. Isso não é
prova de funcionamento ponta a ponta nem de produção.
